Binary search trees are a fundamental data structure used to store data in a way that allows fast lookup, insertion, and deletion. A binary search tree, often abbreviated BST, is a binary tree in which every node has at most two children, referred to as the left child and the right child. The defining property of a binary search tree is that for every node, all values in the left subtree are smaller than the node's value, and all values in the right subtree are larger than the node's value. This ordering property is what allows efficient searching, because at each step the algorithm can discard half of the remaining tree.

Searching in a binary search tree starts at the root node and compares the target value to the current node's value. If the target is smaller, the search moves to the left child; if the target is larger, the search moves to the right child; if the values are equal, the search is complete. This process repeats until the target value is found or a null child is reached, meaning the value is not present in the tree. In a balanced binary search tree, this search takes logarithmic time relative to the number of nodes, because each comparison eliminates roughly half of the remaining candidates.

Insertion into a binary search tree follows the same comparison logic used during search. The algorithm walks down the tree from the root, moving left or right based on comparisons, until it reaches a null position where the new node can be attached as a leaf. Because insertion does not rebalance the tree, repeatedly inserting sorted data can produce a degenerate tree that behaves like a linked list, with search, insertion, and deletion all taking linear time instead of logarithmic time.

Deletion is the most complex operation on a binary search tree because removing a node can break the ordering property if handled incorrectly. If the node to delete has no children, it can simply be removed. If it has one child, the child replaces the deleted node's position. If it has two children, the standard approach replaces the deleted node's value with its in-order successor, which is the smallest value in its right subtree, and then deletes that successor node instead.

Balanced variants of binary search trees, such as AVL trees and red-black trees, were developed to prevent the degenerate, linked-list-like behavior that can occur with a plain binary search tree. These balanced trees enforce additional rules during insertion and deletion to guarantee that the tree's height stays logarithmic in the number of nodes, which in turn guarantees that search, insertion, and deletion all remain efficient even in the worst case. Red-black trees are widely used in real-world software, including many standard library implementations of ordered maps and sets.
