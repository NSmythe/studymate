A hash table is a data structure that stores key-value pairs and allows near-constant-time lookup, insertion, and deletion. It works by passing each key through a hash function, which converts the key into an integer called a hash code. That hash code is reduced modulo the table size to produce an index, called a bucket, where the value is stored.

A good hash function should distribute keys evenly across buckets so that no single bucket becomes overloaded. If two different keys hash to the same bucket, this is called a collision. Collisions are unavoidable in practice because the number of possible keys is usually larger than the number of buckets, a fact known as the pigeonhole principle.

One common way to handle collisions is chaining, where each bucket holds a small list of all key-value pairs that hashed to that index. Looking up a key then requires scanning the short list in that bucket for a match. Another approach is open addressing, where a colliding key is placed in a different, nearby open bucket according to a probing sequence, such as linear probing or double hashing.

The load factor of a hash table is the ratio of the number of stored elements to the number of buckets. As the load factor grows too high, collisions become more frequent and performance degrades, so many implementations automatically resize and rehash the table once the load factor crosses a threshold such as 0.7. Resizing allocates a larger bucket array and reinserts every existing element using the new table size.

Under reasonable assumptions about the hash function and load factor, lookup, insertion, and deletion in a hash table run in average-case constant time, often written as O(1). In the worst case, however, if many keys collide into the same bucket, these operations can degrade to O(n), where n is the number of elements, because every lookup must scan a long chain. This worst case is why hash function quality and load factor management matter so much in practice. Hash tables are used throughout real software, including dictionaries, caches, and database indexes.
